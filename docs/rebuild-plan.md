# Rebuild plan: API + React frontend

Branch: `rebuild`. Every phase lands here; `main` keeps the current Streamlit app
until the rebuild is accepted. Goal: fast and accurate. Running cost is not a constraint.

## Decisions (2026-11-05)

| Topic | Decision | Why |
|---|---|---|
| WC 2026 page (`app.py`) | Delete | No model behind it; tournament is over; Optimizer already covers upcoming picks + Kelly sizing. Claude per-match analysis can return later as an endpoint. |
| Backend | Python, FastAPI, thin layer over `model/` | The model is pandas/sklearn/numpy and the optimizer simulates in numpy per request. Go/PHP would mean rewriting it or a second runtime. |
| Contract | `openapi.yaml`, hand-written, source of truth | Pydantic models generated with `datamodel-code-generator`, TS client with `openapi-typescript`. No code-first spec. Errors as RFC 9457 problem details with stable codes. |
| Frontend | React + Vite + TypeScript SPA | Built to static files and served by the same FastAPI container: one service, one deploy. |
| Languages | English + Greek in the UI | Pick i18n approach in phase 2 (typed dictionary vs `react-i18next`). |
| Auth | None in the app | Locked with Toft access control. |
| Paper-trading job | GitHub Actions until phase 3, then a Toft worker + Postgres | Toft has only `web`/`worker` service types, no cron type: the worker runs a scheduler. |
| Model code (`model/`) | Untouched in phases 1–2 | Michalis owns it; he is on board with leaving Streamlit. |

## Layers

- **Transport**: FastAPI routers. Parse, call a use case, map to the contract.
- **Application**: use cases (`list_picks`, `results_summary`, `edge_sweep`, `optimize_coupon`, `live_odds`).
- **Domain**: `model/` as it is.
- **Infrastructure**: `LedgerRepository` (CSV now, Postgres in phase 3: the interface has two real implementations), Odds API client (`model/live_odds.py`), server-side cache.

Weight: service + repository. No aggregates: this is reporting and computation.

## Phases

### Phase 1: API (no frontend yet)
- Write `openapi.yaml`: picks, all predictions, settled results + metrics, edge sweep, probability report, live odds, `POST /optimize`.
- Generate Pydantic models; FastAPI app under `api/`; delete `app.py` (WC page).
- Odds API key server-side (Toft secret); cache live odds responses server-side with a TTL (speed + saves the 500 credits/month).
- Measure `POST /optimize` (20k simulations) per request before deciding on caching.
- **Check**: pytest per endpoint against a fixture ledger; every response validated against `openapi.yaml`; golden tests prove API numbers equal what the current Streamlit pages compute from the same ledger (accuracy).

**Outcome (2026-11-05)**: `openapi.yaml`, `api/` (contract generated by `scripts/generate-contract.sh`), 104 tests incl.
golden parity with both pages. Live odds are fetched inside `POST /optimize` (per-league 10 min cache, no
separate refresh endpoint). `POST /optimize` measured at p50 22 ms (snapshot) / 55 ms (live, cache warm) in-process
on a laptop with fixture-sized ledgers: no result caching. Known divergence from the page: live odds that match
nothing give no legs (the page silently falls back to snapshot odds).

### Phase 2: Frontend
- Vite + React + TS, generated client (`openapi-typescript` + `openapi-fetch`), chart library chosen in this phase.
- Pages: Paper Trading, Optimizer; EN/EL switch.
- Dockerfile: Node build stage → Python runtime serving `/api/*` and the static build. Delete Streamlit and `pages/`.
- CI: `tsc --noEmit`, frontend build, API tests, image build.
- **Check**: parity checklist from the current Streamlit pages, screenshot per page in both languages, CI green.

**Approved (2026-11-05)**: react/react-dom 19.3.1, vite 8.3.6, @vitejs/plugin-react 6.2.1, typescript 7.0.2 (fall back
to 5.x if `tsc --noEmit` misbehaves), @types/react(-dom) 19.3.0, openapi-typescript 7.13.0, openapi-fetch 0.17.0,
recharts 3.10.1 (check each is ≥ 2 weeks old before pinning). No i18n library (typed EN/EL dictionary, missing key =
type error), no router (page in the URL), no TanStack Query (small fetch hook with abort), plain CSS. Contract adds
`Leg.min_odds = (1 + min_edge) / p_model` ("bet only at these odds or better", used to check Greek bookmakers by
hand). Before deleting `pages/`, freeze the pages' outputs on the fixtures as JSON so the golden tests keep comparing
the API against Michalis's originals. FastAPI serves the build at `/`; Docker gets a Node build stage pinned by digest.

**Outcome (2026-11-05)**: `web/` (React 19, Vite, recharts, typed EN/EL dictionary, page + language in the query
string). Deviations from the approved list: typescript 5.9.3 (openapi-typescript 7.13 needs `typescript@^5`), vite 8.3.5
and @vitejs/plugin-react 6.1.2 (8.3.6 / 6.2.1 were under two weeks old). `src/schema.d.ts` is generated by every
`npm run build` / `typecheck` and gitignored, so it cannot drift. The pages' outputs on the fixture ledgers are frozen
in `tests/fixtures/golden_*.json` (25 cases, re-recording is byte-identical, a 1e-9 change fails, verified with
"today" faked 35 days later); `pages/`, streamlit and plotly are gone. `Leg.min_odds` added. Live odds run only on
an explicit button press (a slider change after the 10 min cache would otherwise spend credits silently); snapshot
odds re-run on every change. Bundle 197 kB gzipped (recharts), not split. Checked by hand in Chrome on the fixture
ledgers: both pages, both languages, tables, metrics, both charts, no console errors.

### Phase 3: Job on Toft
- Postgres service (volume + backups); schema with constraints, e.g. `UNIQUE (strategy, match_date, home, away)`; reversible migration.
- One-off CSV → Postgres import; `LedgerRepository` Postgres implementation.
- Worker service: same image, scheduler command, Tue + Fri 07:00 UTC.
- Disable `.github/workflows/paper-trading.yml`.
- **Check**: one run on Toft; row counts match the CSVs; rollback (re-enable the workflow, CSV reader) tested.

**Approved (2026-11-05)**: `psycopg[binary]` 3.3.6 (3.3.7/3.3.8 under two weeks old); own SQL migration runner
(`api/migrate.py`, up/down files) instead of Alembic + SQLAlchemy. `model/` stays untouched: the worker exports the
database to CSVs in a scratch dir, runs `model.paper weekly` unchanged, writes back in one transaction (new fixtures
inserted; an existing row only gets result + closing columns, only while unsettled). Toft facts (source read):
postgres:16 add-on (panel only), no DATABASE_URL injected, worker has no health check, `start_command` applies to
git builds, no cron, `migrate_command` runs in the new image before it starts and aborts the deploy on failure,
backups = one restic run over raw volumes per machine (not a consistent Postgres backup: the worker writes a CSV
export to its volume after each run instead).

**Progress (2026-11-05)**: step 1 (`api/migrations/0001_ledgers`, `api/migrate.py`, CI Postgres service) and step 2
(`PostgresLedgers`, `api/sync.py`) done, uncommitted. Every API + golden test runs on CSV and Postgres; the real
ledgers (48 + 145) import under all constraints and read back equal. `PostgresLedgers.read` p50 20 ms on Docker
Desktop (connect 6.5 ms, query 1.5 ms, the rest building the frame): no cache, no pool. Next: step 3 (worker).

## Open risks

- Data sources, zero budget for now: football-data (history), The Odds API free tier (live + Pinnacle), Bzzoiro
  (free, Greek league xG/odds, one-person hobby: use with fallback, never sole source). Paid Greek-bookmaker odds
  (Odds-API.io from £49/mo) only once paper trading shows positive CLV.
- Understat blocks GitHub runners. Mitigated 2026-11-05 (main `1329dea`): the job uses cached xG and keeps going;
  the paper strategies don't use xG. A model that needs fresh xG needs another source or a non-GitHub runner.
- Ledgers ship inside the image: after each Tue/Fri run the app shows the new ledgers only after a deploy (Streamlit
  Cloud redeployed on push). Decided 2026-11-05: until phase 3 the app reads them from GitHub `main` at runtime
  (`api/ledgers.py` `GithubLedgers`, 10 min cache, image copy as fallback); phase 3 deletes it.
- Rebuilding Michalis's pages means new model work must be exposed through the API, not a new Streamlit page.
